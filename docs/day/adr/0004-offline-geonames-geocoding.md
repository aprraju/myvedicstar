# ADR-0004: Offline GeoNames geocoding for "City, State[, Country]"

- Status: Accepted
- Date: 2026-09-29

## Context

Users specify a location as "City, State, Country", as "City, State" plus the browser's position, or as the browser's
position alone. Place names must be turned into coordinates, and browser coordinates into a country (to disambiguate
"City, State") and a display name. The options:

1. **Online geocoders (Azure Maps, Google, Mapbox).** Complete coverage down to street level. Each needs an API key,
   costs money per request, adds latency and a runtime dependency, and has terms restricting caching.
2. **Nominatim (OpenStreetMap).** Free, but the public service allows 1 request/second and forbids heavy use;
   production needs a self-hosted instance.
3. **An embedded GeoNames extract.** Cities with population ≥ 5,000 (69,750 places) with state, country, coordinates
   and IANA zone, licensed CC BY 4.0. It is 3 MB compressed, in memory, deterministic and needs no key.

The Panchang needs city-level precision only: sunrise varies by seconds per kilometre.

## Decision

Use the GeoNames extract, generated by `tools/build-geonames-places.cs` and embedded in `.Integration`, behind
`IGeocodingProvider`. Matching is case-, accent- and punctuation-insensitive, and covers primary names, ASCII names,
Latin-script alternate names ("Bangalore", "Bombay"), state names or codes ("Texas", "TX"), and country names, ISO
codes or aliases ("USA", "UK"). Primary names rank above alternate names, then by population. The country-inference
rules live in the Business layer (`PlaceResolver`), not in the provider.

## Consequences

- No keys, cost or network dependency. Lookups take about 1 ms after a one-time load of a few hundred milliseconds.
- Towns under 5,000 people are not found by name; those users can use browser location. An online provider can be
  added behind the same interface.
- The UI must display "Place data © GeoNames (CC BY 4.0)".
- The dataset is refreshed by re-running the tool; place data does not affect Panchang results, so no calculation
  version bump is needed.
