# AST-09 accuracy corpus — measured state (issue #74)

This document records what the AST-09 corpus **actually proves** as of 2026-11-22. It is written to be read alongside
the tests, and it exists because "10,000 cases" is a corpus size, not an accuracy result.

## What the earlier corpus did and did not do

`HorizonsCorpusSpec` could enumerate precisely 10,000 cases and prove the enumeration deterministic. **Nothing ran
them.** A count is not a measurement, so the suite was green while no case had been scored against an independent
reference.

## What this change adds

- `CorpusAccuracyHarness` evaluates **every** enumerated case and gives each exactly one status:
  `Scored`, `OutOfTolerance`, `NoReference`, `NotComputable`, `NotALongitude`, `NotMeasurable`. No case is silently
  skipped and none is counted as passing without being compared.
- `ReferenceBackedCorpusScoringTests` scores the 14 committed Horizons rows directly, so the harness can fail when the
  engine drifts on a body the reference actually covers.
- `CorpusEvaluationReport` renders the per-category counts from the run, so the report cannot drift from the suite.

## The measured distribution (pinned in `CorpusAccuracyHarnessTests`)

| Outcome | Cases | Why |
|---|---|---|
| `NoReference` | 5,335 | Body is computable, but no committed Horizons row exists at the case's instant |
| `NotComputable` | 2,665 | Uranus, Neptune, Pluto (no orbit beyond Saturn) and True Node (no implementation) |
| `NotALongitude` | 2,000 | Transition/sunrise/Lagna/ayanamsa/historical categories are not geocentric longitudes |
| `Scored` / `OutOfTolerance` | **0** | No generated instant lands on a committed reference epoch |

**Zero of 10,000 cases are scored.** That is the honest state, and it is pinned as an assertion so it cannot be
quietly assumed otherwise: the day a reference set covers the corpus, that assertion fails and someone records the real
accuracy result instead of letting a green suite imply one.

## What IS measured: the 14 committed rows

Residuals in arcseconds, engine minus JPL Horizons (DE441), checked in and pinned in
`ReferenceBackedCorpusScoringTests`:

| Body | JD 2451545 | JD 2461115 |
|---|---|---|
| Sun | 13.708 | 6.387 |
| Moon | 41.716 | 25.247 |
| Mercury | 65.871 | 1298.957 |
| Venus | 48.253 | 1263.974 |
| Mars | 48.039 | 1314.643 |
| Jupiter | 360.780 | 1321.602 |
| Saturn | 561.706 | 1054.584 |

**These are measurements, not targets.** The owner's 1 arcsecond planet target is **not met** by these rows and is not
claimed here. The solar residual's cause is a documented, unresolved finding in
`horizons-reference.json` → `provenance.aberrationAnalysis` (the residual is **NOT consistent** with the 20.4955″
aberration term).

## Falsification

Adding 0.01° (36″) to the solar longitude turns two tests red. Perturbing the mean-node series coefficient by a relative
`2×10⁻¹⁰` does **not** — correctly, because that is ~0.007″ over the corpus span, an amount no budget should catch.

## Why the reference set was not enlarged

Filling 10,000 instants with reference values would require either
JPL Horizons (network at test time — forbidden by the architect's constraint) or values generated by the
implementation under test (self-reference — forbidden by AC-3). Neither is acceptable, so the gap is **reported**
rather than hidden. The obligation is recorded, and it belongs to whoever refreshes the fixture set.

## Not claimed

- No accuracy threshold is met for the planets or the Moon.
- No case in the 10,000-case corpus was scored.
- The reference set does not yet cover the corpus's instants.
